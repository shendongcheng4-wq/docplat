# docplat —— 中文扫描书的批量 OCR 与校对流水线

把一个装满扫描图（一本/一套书）的目录，跑成一份**干净、可直接读的 txt**。

不是「调个 OCR 完事」，而是在模型外面套了三道判断：**跑之前**用已验证清单决定走哪条通道，
**跑之后**用输出形态判断这页要不要换模型重读，**跑不完/读不好**的页进人工队列而不是混进正文。

针对的是 OCR 最难的一类材料：繁体古籍 / 地方志 / 族谱 / 内部资料 —— 竖排、世系表、
图版扉页、透印空白页、大量表格。实测 2400+ 页，7 本书。

---

## 为什么不是「接个模型就完了」

主流做法是把每页丢给 VL 模型，拿回 markdown 拼起来。真跑起来会撞上四件事：

| 现象 | 后果 | docplat 的做法 |
|---|---|---|
| 表格/世系表页用纯文本模型读，结构全丢 | 一条记录被切成两行，数字串行 | 输出侧结构闸门：行短、行多 → 升级到 VL 重读 |
| VL 模型 35 s/页，全量跑 242 页要 136 分钟 | 一本 2000 页的书要跑两天 | 只对真正需要结构的页升级，**4.2x 提速** |
| 空白页 / 透印页，模型会编内容 | 「国家统一」政治试题混进地方志正文 | 判空白 + 落空文件，正文里一个字都不留 |
| 读不好的页，模型回一句 "too blurry…" | 这句英文被当成正文导出 | 一律识别成空白页，不进正文、不进队列 |

## 架构

```
                    ┌─────────────────────────────────────────┐
  扫描图目录  ──▶   │ import    算 hash 去重 / 读尺寸 / 按页号排 │
                    └────────────────┬────────────────────────┘
                                     │
                    ┌────────────────▼────────────────────────┐
                    │ 预路由  命中已验证版面清单 → 直接定通道   │
                    │        未命中 → （可选）PP-DocLayout     │
                    └────────────────┬────────────────────────┘
                     glm 通道        │        vl 通道
              ┌──────────────────────┴──────────────────────┐
              │  GLM-OCR (llama.cpp)      PaddleOCR-VL      │
              │  1.95 s/页 · 4.5 GB      35 s/页 · 14.8 GB  │
              └──────────────────────┬──────────────────────┘
                                     │
                    ┌────────────────▼────────────────────────┐
                    │ 结构闸门（跑完之后才判）                  │
                    │ 行数≥10 且 行字中位数≤8 且 短行≥80%      │
                    │ → 这是分格条目，换 VL 重读                │
                    │ 列数对不齐（>25% 行）→ 也换 VL            │
                    └────────────────┬────────────────────────┘
                                     │
                    ┌────────────────▼────────────────────────┐
                    │ 质量闸门 → done / review / failed        │
                    │ 空白页：清空文件，正文与界面都不出现       │
                    │ 复核队列：浏览器里逐页对照原图核心        │
                    └────────────────┬────────────────────────┘
                                     │
                    ┌────────────────▼────────────────────────┐
                    │ export  所有页合成一份 txt（照纸书排版）   │
                    └─────────────────────────────────────────┘
```

**显存约束决定了必须分阶段**：GLM 占 4.5 GB，PaddleOCR-VL 峰值 14.8 GB，
16 GB 卡装不下两个。所以 `--stages glm,vl,retext` 是「跑完一批再换模型」，
不是并行。`auto` 负责在阶段间自己停/起服务。

## 关键设计决策（都有实测依据，不是拍脑袋）

**1. 版面判断放在模型输出侧，不放在图像侧。**
用几何特征判「这页是不是表格」，精确率 17–28%；换 PP-DocLayout-S 预训练模型到 59%，
PP-DocLayout-L 能到 92% 但精确率只有 21%。三次都失败，因为连通域尺度随字号/分辨率变化，
换一本书就崩。改用「GLM 输出长什么样」来判：短行密度是跨书稳定的。

**2. 「有没有字」默认不看图像，但「有没有墨」可以看。**
试过用连通域密度判「这页有没有字」：溧阳旅游文化 210 页里 11 页判对（0 误杀），
但同一套阈值在族谱 242 页上误杀 58 页、在商业志上误杀 276 页 —— 因为连通域尺度随字号和分辨率变。
**换一个问法就成立了**：「这页有没有正印的深墨」。正印墨直接印在纸上，能深到灰阶 20–60；
而隔着一层纸透过来的墨，最深处也只到纸色以下 60–150。这是物理约束，与字号、分辨率无关。
见下面第 6 条。

**3. 空白页必须落空文件，不能只改状态。**
模型对空白页会回一句英文解释。只把数据库状态改成「空白」的话，工作台一翻还是那句英文，
导出层虽然能过滤，但人看到会觉得识别错了。`pipeline.run` 判空白时直接写空文件。

**4. 短页不能一律当空白。**
图版扉页常常只有 4–8 字（「名胜与历史」「名人与溧阳」），跨页断句还有「天目湖——我们共」这种。
判据是 `TITLE_MIN=4`：4–9 字纯中文照正文输出，1–3 字才当模型噪声。

**5. 退化重复要「报」不要「压」。**
模型卡死会把同一块内容吐几千遍。压缩掉看着干净，实则静默丢内容 —— 整块真数据
（捐款名录每笔都叫「懷德堂/伍佰元」）会被洗成「（重复 N 次）」。
现在只判 `review`，压缩阈值 `SQUASH_MIN=20`。

**6. 纸张太薄透出来的背面，要当空白处理。**
实体上是空白页，纸太薄把**同一张纸另一面**的印刷透了过来，而且左右镜像。
模型对这类页只会读成乱码（`业业业业`、`址 址 址`、`休史業布面紫的慰藉的腆物`），
或者干脆编一段（目录页编出几百条「影响因素和影响」），于是一路绿灯进正文。

判据（`docplat/bleed.py`，`plat.bat bleed --doc ID`）：

| 步骤 | 内容 |
|---|---|
| 一 | `c = 纸色(p90) − 最深墨(p0.1)`。`c` 低于全书 p75 的 80% → 这页没有正印深墨 |
| 二 | 但浅灰大字印的章扉页比透印页还淡（p23「第一章…」c=40，透印内衬 c=75），只能看文本 |
| 三 | 用**本书自己的双字词表**：正常页用词与全书共享，乱码是随机字序。实测乱码覆盖率 0.00，章扉页 0.47–0.71 |
| 保护 | 填出了非空表格的页一律不删（浅色油墨印的宽表墨也淡，但它是真内容） |

拿不准的页返回 `None`：不删、不导，留着给人看。实测 16 本书、3100 页，
删掉的全是空白页/透印页/英文拒识声明/空表，误删 0。

**7. 目录页的点线会把 GLM 带进死循环。**

目录行末的「…………」读起来像无限重复：先进性教育活动 p9 读出第一行标题后
就开始吐「…」，一直吐到 6000 token 上限 —— 16 秒、32791 字、压缩冗余 1.00，
质量闸门判「疑似重复生成」，看起来就像"目录页识别不了"。字其实好好的。

`docplat/toc.py` 送图前把点抹掉（同一页重读：731 字、3.7 秒、内容完整）。
判据是「点状小连通域 + 同一水平带够多 + 等距 + 横向铺开」，动作是**只填点自己的
bbox**：

| 坑 | 说明 |
|---|---|
| 别用 32px/900 面积当阈值 | 汉字 15–30px、面积 ≈180，量级太近，第一版把「（2003年06月01日 溧试点办[第35号]）」涂成了方块 |
| 高度才是硬闸门 | 点（含 JPEG 糊成的短横）h≤9px，正文汉字 h≥15px，按高度切干净 |
| 别用 `cy//带宽` 分带 | 一行的点跨在桶边界就被劈成两半，12 行只抹掉 1 行 |
| 别按连通域外框整行涂白 | 点线常和左边文字连成一片，整框涂会吃字 |

触发很窄：只有 GLM 页被判「重复生成」时才抹点线重读一次，正常页零开销。
自检 `python tools/selftest_toc.py`（合成假目录页，验证点抹干净、文字零改动、
无点线页面不被误改）。

**8. 合并单元格的复杂表格会让 GLM 吐一片空单元格 —— 换提示词就能救。**

先进性教育活动 p192（"抓好整改、巩固提高"阶段工作考核细则，竖排表头 + 跨行合并）
在默认提示词 `Text Recognition:` 下：标题、表头、第一行都读对，之后一路吐 `|`，
4071 行 / 4058 个竖线 / 4142 字，结构闸门判「分格条目页」升级 vl。但同一张图换成
一句中文表格指令（`config.GLM_TABLE_PROMPT`），6.2 秒吐出**完整 HTML 表**：
`rowspan/colspan` 都在、23~36 行连同「小计 100」一行不少、1218 字。

- 触发：GLM 页出现「整行只有竖线」的行 ≥50（`pipeline._pipe_degenerate`），
  或质量闸门判了「重复生成」。正常页零开销。
- 接受门槛：重读结果判 DONE **且** 不再退化，否则保留原样。
- 反面：p58「领导联系点登记表」、p132「党内民主评议表」是**没填写的空表单**，
  格子天然是空的（9~13 行 `| | | |`）。那不是退化 —— `quality._empty_grid`
  认它，判 DONE「空白表格（表单未填写）」，不再误报「整块重复生成」。
  上限 200 格，把「上千个空壳」那种真拆格失败挡在外面。

自检 `python tools/selftest_table.py`（9 项：退化判定、空表单、填充表、上千空格子）。

**9. 扫描件 JPEG 里的 EXIF 方向标记，模型看不见 —— 倒置页会把图注小字读丢。**

翻拍/扫描的页面常带 `Orientation=3`（像素已存成 180° 倒置），看图软件和浏览器
会替你转回来，但 llama.cpp（stb_image）和 OpenCV 用的是裸像素，标记被无声忽略，
整页倒着进模型。**对整页正文影响不大**（GLM 倒着也能读，实测字数常常一字不差），
但图注、表格里的小字会成片丢：

- 铁的新四军 p0119（4×4 将军像，16 个名字）：倒着读 0.52 秒、只出 **4 个名字**；
  正过来 1.93 秒，**16 个全出**。「只丢一部分」比全错更难发现，用户就是这么报上来的。
- 全库 7646 页里 **263 页**带方向标记（天目湖之旅「观光」、党旗下的辉煌、
  机关服务品牌集萃、法院回眸、铁的新四军）。

做法：`docplat/imgio.py::upright()` 在喂模型前按 EXIF 转正，GLM / Paddle / 目录抹点线
三处入口统一走它。不写方向标记的图**原路径返回**，零拷贝零开销；要转的在
`data/_upright/` 缓存一份，重跑直接复用。原图一律不动。

存量页用 `python tools/fix_orient.py` 体检（加 `--apply` 写盘）：只按一条硬标准替换
——**正过来后汉字数 ≥ +3** 且不退化。为什么不一律重跑：实测有的页正过来反而更差
（p0093 把「要图」读成「图」），没证据就别动。

自检 `python tools/selftest_imgio.py`（15 项：读标记 / 转 180 / 转 90 换宽高 /
不转的零开销 / 缓存复用 / 坏路径兜底），并用变异（把 upright 改成原样返回）确认会红。

## 快速开始

```bash
# 1. Python 3.10+（开发环境 3.12）
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt

# 2. 起识别服务（另一个终端，要一直开着）
#    需要自己准备 llama.cpp 的 llama-server + GLM-OCR 的 GGUF 权重，见 scripts/glm_serve.py 文件头
python scripts/glm_serve.py

# 3. 导入一卷（目录里直接躺图片，或有个 JPG/ 子目录）
python -m docplat ingest --src "D:\books\某氏宗谱\某氏宗谱（卷一）\JPG"

# 4. 识别（glm 通道）
python -m docplat run --doc "某氏宗谱（卷一）"

# 5. 导出：按导入目录自动推出「丛书\卷名.txt」，默认落 桌面\书籍导出\
python -m docplat export --doc "某氏宗谱（卷一）"
```

Windows 上 `plat.bat` 就是上述入口的包装（`plat.bat run --doc ...`），
`工作台.bat` 起校对界面：**http://127.0.0.1:7788**。

工作台里做的事，都是「别让人一页页点」：

| 操作 | 说明 |
|---|---|
| 左栏队列 | 待人工 / 升级 / 失败 / 低分 / 抽检 / 全部，按「模型最可能读错的排前面」 |
| 左栏字数 | 0 字标红、1~9 字标琥珀 —— 空白页和只剩页脚的页扫一眼就能挑出来 |
| 勾选 + 批量 | 行首复选框，Shift 点选一段，`x` 勾当前页；批量「核对」或「标为空白」 |
| 正文搜索 | 筛选框旁边切到「正文」，全书正文一起搜（空格分隔多个词，全部命中才算） |
| 相邻页 | 正文上方两条灰字：上一页的结尾、下一页的开头，点一下直接跳 |
| 历史版本 | 每次保存改动前自动留一份；`h` 打开，点「恢复这一版」就回去 |
| 页级备注 | `n` 打开。不影响正文，也不改变核对状态（单独一张表） |
| 服务灯 | 顶栏那个圆点 = 识别服务（8081）通不通，15 秒探一次；点开看日志尾巴 |
| 导出体检 | 点「导出全书」先列清单：哪些页还没识别完（导出会被跳过）、哪些可疑没核 |
| 正文排版 | 只读视图就是交付 txt 的排法（段首缩进两格、段间不空行），编辑态给原始分行 |

**导出体检只拦真风险**（`docplat/preflight.py`，2026-11-05 改）：0 字页分两档 ——
`err` 里写着「空白页…」的是流程已经给过结论的（墨淡 / 透印 / 人工判空白），
不弹窗，导出成功的提示里带一句「N 页空白页未计入」；只有「0 字又说不出为什么、
也没人核对」的页才拦人。想恢复成一律拦，把 `config.PREFLIGHT_WARN_BLANK` 置 True。
自检 `python tools/selftest_preflight.py`（9/9）。

历史版本存在 `data/_undo/<文档号>/<hash>/<时间戳>.md`，每页留最近 20 份
（`pipeline.UNDO_KEEP`）。恢复前也会先留一份，所以「恢复错了」还能再撤回来。
判空白页清掉的正文走另一条路，存在 `data/_quarantine/`。

「标为空白」会清空该页正文并记为已核对，原文备份到 `data/_quarantine/<文档号>/`，
点错了能把文件捞回来（库里状态需手工改回，见 `docplat/pipeline.py::batch_action`）。

**「核对」在升级队列里是另一个意思**（2026-11-05 用户报「点了核对怎么还在升级里」）：
待人工队列里核对只是加一条记录、不改 `pages.status`（所以能撤销、能回队列）；
但升级队列里的页是 `channel=vl, status=pending`，核对等于说「这页 GLM 的结果我认了，
不用再换 Paddle」—— 这时候必须把这页**收成 done**，否则它永远挂在升级队列里，
进度条也永远差这几页跑不满（这本 550 页的书当时就卡在 540）。

```
核对 → status=done，err="人工核对：采用当前结果，不再换 Paddle（原判：结构闸门升级：…）"
撤销 → status=pending，err 还原成原来那句「结构闸门升级：…」，重新出现在升级队列
```

整批换 Paddle 重跑（`store.pending`）会跳过已核对的页，免得把人工确认过的正文冲掉；
工作台「重跑本页」是显式指定 hash，照跑不误。自检 `python tools/selftest_queue.py`
（19 项，跑在临时库上：核对/撤销往返、批量跳过、显式重跑、普通页不受影响）。

整套书一次跑完：

```bash
plat.bat auto --root "D:\books\某氏宗谱" --stages all
```

## 常用命令

| 命令 | 用途 |
|---|---|
| `docplat docs` | 列出已入库文档、页数、来源目录 |
| `docplat ingest --src DIR` | 扫目录入库（幂等，重复导入不翻页） |
| `docplat run --doc ID [--channel glm\|vl]` | 跑识别 |
| `docplat queue --doc ID --kind review` | 看人工待核队列 |
| `docplat export --doc ID [--md]` | 合并成 txt（段首缩进两格、段间不空行；`--md` 保留表格管道） |
| `docplat bleed --doc ID [--apply]` | 找出空白页背面的透印，清成空白（默认只报告） |
| `docplat retext --doc ID` | vl 失败的图页换纯文本模型重读 |
| `docplat serve --port 7788` | 校对工作台 |
| `plat.bat auto --root DIR --stages glm,vl,retext` | 批量：导入→识别→导出 |

## 自检

不需要 GPU、不需要模型、不需要任何真实书页：

```bash
python tools/selftest_router.py     # 版面路由 6/6
python tools/selftest_text.py       # 交付排版 9/9
python tools/selftest_bleed.py      # 透印判据（要本机有书页图，见下）
```

用合成图和仓库自带的版面真值清单（`tests/fixtures/`），把「预路由 → 结构闸门 → 升级 →
第二轮跑完 → 队列清空」这条控制流走通。改闸门逻辑前后各跑一次。

`selftest_bleed` 用的是 `tests/fixtures/bleed_cases.json`：把**已经人工核过的现状**
（该判空白的页 / 必须留的正文页和章扉页 / 拿不准的页）冻成样本。改 `bleed.py` 的判据后跑一次，
就知道有没有把该留的删掉 —— 以前这件事只能靠全库重跑 + 人眼抽 3000 页。

样本取自本机书籍（书名、页号、图片路径），所以不进仓库。自己生成：

```bash
python tools/make_bleed_fixture.py --write    # 图片默认在 ~/Desktop/书籍，可用 DOCPLAT_BOOKS 指定
```

`tools/eval_router.py` 才是量化答案（召回/误报/提速比），但它需要一份 v1 数据集，
见 `tools/_paths.py` 的说明 —— 那份数据是书页，不进仓库。

## 已知限制

- **幻觉是模型的问题，不是流水线能根治的**。模型对糊图/透印页会编出成段中文，
  而且会跑题（在一本地方志里编出政治试题）。目前靠人工抽查 + 主题词覆盖率筛查，
  没有自动闸门。宁可留 review，不要静默通过。
- **宽表会截断**。GLM 的上下文 8192 token，30 列以上的折页统计表读不完，
  需要 `--ctx 16384` 重启服务。程序会补闭合标签按行摊开，但内容确实缺。
- **图像侧判版面/判有无文字都不可行**（见上文实测），所以省不掉模型时间。
- **PaddleOCR-VL 耗时随图像面积线性增长**：36 MP 的图 4 分钟/页，
  代码会先压到长边 3200 再送模型（`VL_MAX_SIDE`）。
- Windows 优先：`plat.bat`、`taskkill`、CRLF/GBK 的坑都是按 Windows 调的。
  Linux 下核心逻辑能跑，`glm_serve.py` 的停止逻辑已做 POSIX 分支，但没实测。
